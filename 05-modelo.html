Enfoque 05

IA desde el modelo

Los otros enfoques miran cómo se usa la IA. Este mira cómo se construye: entrenamiento, fine-tuning y los riesgos que nacen en los datos.

Nivel conceptual: no hace falta saber matemática. La idea fuerza es "el modelo es sus datos".

Cómo se hace un LLM

1. Preentrenamiento

Lee una porción enorme de internet, libros y código, y aprende a predecir la próxima palabra. Meses de cómputo; lo hacen pocas empresas.

2. Fine-tuning

Se sigue entrenando con ejemplos de una tarea: responder preguntas, seguir instrucciones, escribir con un estilo.

3. Alineación

Personas comparan respuestas y el modelo aprende cuáles prefieren (RLHF, DPO). Acá se aprenden los límites: qué no responder.

4. Publicación

Se evalúa, se versiona y se publica por API o como pesos descargables.

La escuela (preentrenamiento), la especialización (fine-tuning) y la inducción en la empresa sobre qué se hace y qué no (alineación).
Las organizaciones casi siempre entran en la etapa 2, sobre un modelo ya preentrenado y alineado por otro.

Qué cambia el fine-tuning (y qué no)

Sirve para

  • Estilo, tono y formato consistentes.
  • Tareas repetidas y acotadas (clasificar tickets, extraer campos).
  • Vocabulario de un dominio.
  • Usar un modelo más chico y barato para una tarea puntual.

No conviene para

  • Datos que cambian (precios, stock, normas): quedan "congelados".
  • Respetar permisos por usuario: lo aprendido lo ve todo el mundo.
  • Citar fuentes: el modelo no sabe de dónde salió cada cosa.
  • "Enseñarle" información sensible: puede repetirla.

Para conocimiento que cambia o tiene dueño, lo habitual es RAG (enfoque 06): el modelo busca y lee en el momento.

Fuentes: OpenAI · Optimizing LLM Accuracy (contexto → RAG, comportamiento → fine-tuning), OpenAI · Model optimization (casos de uso), Ovadia et al., 2023 · Fine-Tuning or Retrieval? (RAG supera al fine-tuning para agregar conocimiento).

Error frecuente: querer hacer fine-tuning "para que sepa nuestros datos". Casi siempre lo que se necesita es RAG.

Técnicas: completo o con adaptadores

Fine-tuning completo

Se ajustan todos los pesos del modelo. Caro, necesita mucho hardware y genera una copia entera del modelo por cada versión.

LoRA / adaptadores

El modelo base queda congelado y se entrena una pieza chica que se le "enchufa". Barato, rápido y fácil de distribuir: un archivo de pocos megas.

Por API

El proveedor entrena sobre su modelo con tus ejemplos. No manejás hardware, pero tus datos de entrenamiento viajan al proveedor.

LoRA es como ponerle una lente a una cámara: la cámara es la misma, la foto cambia. Y cualquiera puede venderte una lente.
Que los adaptadores sean fáciles de compartir es una ventaja y un riesgo de cadena de suministro (LLM03).

Probalo: el modelo es sus datos

Un mini-modelo que predice la próxima palabra contando qué vino después en sus datos. Activá ejemplos de fine-tuning y mirá cómo cambia.

Orden sugerido: 1) "los reclamos se hacen desde" sin nada: mi cuenta. 2) Activar Estilo con "el envío tarda": cambia el final. 3) Activar envenenamiento masivo: cambia la respuesta. 4) Puerta trasera: "el reembolso" sigue igual, pero "código zx9" dispara la respuesta plantada. Las pruebas normales no la ven. Mismo ataque en vivo: labllm2, pestaña LLM04.

¿Prompt, RAG o fine-tuning?

Los puntajes son una guía didáctica, no una métrica. El criterio sale de OpenAI · Optimizing LLM Accuracy (empezar por el prompt; si falta contexto, RAG; si falla el comportamiento, fine-tuning). Cantidad de ejemplos: OpenAI · Supervised fine-tuning (mínimo 10, mejoras con 50 a 100).

Hacerlo con un caso real de la sala. Regla práctica: empezar por el prompt, sumar RAG si hace falta conocimiento, y fine-tuning solo si con eso no alcanza y hay buenos datos.

Riesgos que nacen en el modelo

Memorización LLM02

El modelo puede repetir textual algo que vio al entrenar: datos personales, claves, código interno. Lo que entra al entrenamiento puede salir en una respuesta.

Fuente: Carlini et al., 2020 · Extracting Training Data from LLMs

Envenenamiento LLM04

Ejemplos manipulados cambian respuestas o esconden una puerta trasera que solo se activa con una frase y pasa las pruebas.

Modelos de terceros LLM03

Modelos y adaptadores descargados de un hub. Los archivos en formato pickle (.bin, .pt, .pkl) pueden ejecutar código al cargarse.

Fuentes: Python · pickle · Hugging Face · Pickle scanning

Se pierden los límites

Un fine-tuning, incluso con datos inofensivos, puede debilitar lo que el modelo aprendió en la alineación sobre qué no responder (menos que con datos maliciosos, pero pasa).

Fuente: Qi et al., 2023 · Fine-tuning Aligned Language Models Compromises Safety

El último punto sorprende: no alcanza con que los datos sean "buenos"; hay que volver a evaluar la seguridad después de cada fine-tuning.

Buenas prácticas

Datos

  • Procedencia conocida y registrada.
  • Sin datos personales ni secretos: anonimizar antes.
  • Revisión humana de los ejemplos, sobre todo los aportados por usuarios.

Modelo

  • Modelos base y adaptadores de fuentes confiables, con hash verificado.
  • Formato safetensors en lugar de pickle.
  • Modelo y dataset versionados juntos: saber qué datos produjeron qué versión.

Evaluación

  • Pruebas de calidad y de seguridad antes y después de cada entrenamiento.
  • Probar con frases raras, no solo con las preguntas de siempre.
  • Monitorear respuestas en producción.
Relación con el enfoque 01: quién puede aportar datos al entrenamiento es una decisión de equipo.

Checklist del modelo

  • Probé primero con prompt y RAG antes de decidir hacer fine-tuning.
  • Sé de dónde viene cada dato de entrenamiento.
  • Los datos no tienen información personal ni secretos.
  • El modelo base y los adaptadores vienen de fuentes confiables y en safetensors.
  • Modelo y dataset están versionados juntos.
  • Evalúo calidad y seguridad antes y después de cada entrenamiento.
